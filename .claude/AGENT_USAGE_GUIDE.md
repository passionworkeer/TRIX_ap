# Agent 集群使用指南 v2.0

## 🎯 核心理念

**质量优先，安全第一，小步快跑**

每次改动：
1. ✅ 安全专家必查
2. ✅ 质疑 Agent 挑刺
3. ✅ 小改动 (< 100 行)
4. ✅ 立即 Git 提交

## 📊 新的工作流程

### 阶段 1: 需求分析 (质疑 Agent 挑战)

```
你: "添加登录功能"

🔍 主 Agent 分析
   → 涉及前端、后端、数据库、安全

💥 质疑 Agent 挑战
   → "是否可以用 Supabase Auth 而不是自实现？"
   → "是否需要记住登录状态？"
   → "是否有第三方登录需求？"

📋 精炼需求
   → 使用 Supabase Auth
   → 支持记住登录
   → 暂不支持第三方登录
```

### 阶段 2: 方案设计 (质疑 Agent + 安全专家)

```
🎨 专家设计方案
   → 前端: 登录表单组件
   → 后端: 集成 Supabase Auth
   → 数据库: 使用 Supabase 内置表

💥 质疑 Agent 挑战
   → "表单验证是否在前端？需要后端验证吗？"
   → "token 存在哪里？localStorage 还是 cookie？"
   → "错误处理是否完善？"

🛡️ 安全专家审查
   → "必须使用 HTTPS"
   → "token 必须安全存储"
   → "必须有速率限制"

📋 优化方案
   → 前后端双重验证
   → 使用 httpOnly cookie
   → 添加速率限制中间件
```

### 阶段 3: 小步实施 (质疑 Agent + 安全专家 + Git)

```
🔨 小步 1/5: 登录表单基础结构
   前端专家: 实现 JSX 结构
   💥 质疑: "表单元素是否使用了正确的 type？"
   🛡️ 安全: "输入是否正确转义？"
   ✅ 通过 → Git commit: "feat: 添加登录表单基础结构"

🔨 小步 2/5: 表单验证
   前端专家: 添加邮箱和密码验证
   💥 质疑: "验证规则是否严格？密码强度要求？"
   🛡️ 安全: "是否有防暴力破解机制？"
   ✅ 通过 → Git commit: "feat: 实现表单验证逻辑"

🔨 小步 3/5: 集成 Supabase Auth
   前端专家: 实现 signInWithEmailAndPassword
   💥 质疑: "错误处理是否完善？网络异常怎么办？"
   🛡️ 安全: "token 是否安全存储？"
   ✅ 通过 → Git commit: "feat: 集成 Supabase Auth"

🔨 小步 4/5: 路由保护
   前端专家: 实现 ProtectedRoute 组件
   💥 质疑: "未登录用户能否直接访问？"
   🛡️ 安全: "检查通过 ✅"
   ✅ 通过 → Git commit: "feat: 实现路由保护"

🔨 小步 5/5: 错误提示
   前端专家: 添加友好的错误提示
   💥 质疑: "错误信息是否泄露敏感信息？"
   🛡️ 安全: "检查通过 ✅"
   ✅ 通过 → Git commit: "feat: 添加错误提示"
```

### 阶段 4: 完整审查

```
🛡️ 安全专家全面审查
   → OWASP Top 10 检查
   → 依赖漏洞扫描
   → 认证授权审查
   → 敏感信息检查

💥 质疑 Agent 全面挑刺
   → 设计合理性
   → 代码质量
   → 性能问题
   → 可维护性

🧪 测试专家测试
   → 单元测试
   → 集成测试
   → E2E 测试
   → 覆盖率 > 80%

📊 质量评分
   → 安全性: 9/10 ✅
   → 性能: 8/10 ✅
   → 可维护性: 8/10 ✅
   → 成本效益: 8/10 ✅

🎯 结论: **通过** ✅
```
